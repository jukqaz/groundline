# Optional usage assessment and experiments

Read only for a requested maturity assessment, benchmark, or counterfactual
projection. Ordinary task selection does not require this workflow.

## Artifact-backed maturity

Define person/team, time window, repositories and available artifacts. When
starting from histories, consume the existing Codex Evidence Packet from
`audit-agent-history`. Prefer diffs, tests, runtime and release evidence over
self-report. An optional Chronicle aggregate follows its bundled contract.

Score scope control, context discipline, verification, safety, reuse and release
closure from 0 to 4. Explain each score with the observed evidence, coverage,
exclusions and uncertainty; score workflow quality, not intelligence. Cap weak
verification when polished output was accepted without relevant checks. Compare
prior assessments only when their populations and criteria match. Prioritize
next useful behavior, its owner and acceptance check; no fixed output heading
or recommendation count is required. Add a growth challenge only when requested
or already active. Keep Chronicle experiment state and ledgers independent.

## Paired evaluation

Use representative actual tasks with the same inputs, acceptance criteria, tools,
runtime, service tier and permissions. Hold model/effort and delegation constant
when testing guidance; change one factor at a time when testing selection.
Predeclare protected outcomes and primary resource metric. Include failed work,
rework and integration cost in total owned tokens and elapsed time. Missing
resources stay unknown; tool latency is not model speed. Review output quality
against acceptance checks rather than length or agreement with the guide.

Use a healthy verification baseline before claiming gains. A missing baseline
limits that claim, not authorized repairs or implementation. Keep one tracked
trial active unless independent comparisons were requested. Use the
[personal improvement contract](personal-improvement.md) for persistent personal
guidance trials; do not write a new ledger or collect raw content. Sample
readiness is not statistical confidence, causal savings or future quality proof.

## Requested projections

`groundline efficiency simulate --audit <audit.json> --json` consumes one existing
supported redacted session, weekly or combined weekly-review audit. Reuse its
bytes instead of recollecting. Weekly simulation covers observed root counters,
not delegated or Guardian usage. Multiple inputs are rejected because their
ownership and overlap cannot be established.

Schema 2 labels its fixed scenarios `lower_reduction_assumption`,
`middle_reduction_assumption` and `higher_reduction_assumption`. Report the actual
fractions, observed resource scope and assumptions separately. These are not
forecasts, learned effects or measured savings. Required token splits need native
availability evidence and a known source; missing values cannot become zero.
Zero-token baselines are INCONCLUSIVE with null reduction ratios. Older evidence
without availability metadata cannot support projection; do not rerun collection
merely to produce one. Never convert tokens to billing or subscription savings.
