# Task selection and workflow assessment

Keep native Codex in charge of execution. Select for the requested outcome,
current phase and acceptance checks; preserve explicit model/effort choices and
permissions. Optimize GPT-6 Astra, Sol and Luna only. Historical records and
explicit older selections remain intact, outside optimization scope.

## Choose the relevant route

- **Task or lane selection:** use [model and effort guidance](../../references/model-effort-routing.md).
  Select model and effort independently, including supported xhigh/max when
  depth is needed. Use the active host's catalog/tools; bundled metadata does
  not prove account access. Reassess at a meaningful phase change, not every turn.
  Ordinary task selection needs no usage audit, maturity score or comparison quota.
- **Independent implementation or research lanes:** this skill requests bounded
  native subagents when useful root work can continue and results can be integrated.
  Give each lane a concrete output, relevant context, acceptance checks and
  disjoint edit ownership. Choose its supported model/effort under the guide;
  respect an explicit no-delegation policy. Integrate and verify returned work.
  Keep small sequential work local; an assessment-only request remains advisory.
- **Usage-driven replacement of an existing choice:** use [evidence routing](../../references/evidence-routing.md).
  Reuse relevant conversation evidence and available aggregates. Only matched
  direct outcomes support an empirical replacement; missing history leaves that
  comparison inconclusive without blocking ordinary authorized work. The CLI
  does not guess a model from task labels or change native settings.
- **Workflow review or product improvement:** use [the optimization loop](../../references/codex-optimization-loop.md).
  Consult [capability routing](../../references/capability-routing.md) only for a
  relevant opportunity. Feature use is worthwhile when it helps the outcome.
  For a requested maturity score, benchmark or projection, use
  [usage assessment](../../references/usage-assessment.md).

Resolve references from this installed plugin. Read
[command resolution](../../references/platform-commands.md) only when a CLI is needed.

## Preserve completion and evidence

Carry the goal, user corrections, authority, completed checks and remaining
acceptance work across phases. Pass only decision-relevant context to children.
A request to verify runtime behavior, appearance or deployment may close an
existing acceptance gap; it is not automatically rework or a model failure.
Escalate for demonstrated reasoning difficulty, not permission/network failures.

For requested usage-driven adaptation, after an agreed delivery is assessed,
use [delivery evidence](../../references/delivery-evidence.md) to record its actual
result privately. Separate proposed, requested and observed effective selections;
include failures and unknowns. Do not replay completed work to fill a sample quota.
Keep conversation text, credentials and private provider state out of reports.

Report the choice or change, its evidence and the remaining verification gap
concisely. A task judgment is not a measured optimum; a successful synthetic
test is not proof of live quality, activation or savings. No global setting,
scheduled task, new chat or permission expansion is implied by this skill.
