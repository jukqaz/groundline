# Reduce repeated workflow friction

Read [conversation improvement](../../references/conversation-improvement.md)
when the user requests improvement or an authorized routine reviews actual
feedback. Start with a relevant previous change and the necessary conversation
context, including a counterexample. Separate assistant mistakes from changed
requirements and exploration. No justified change is a normal result.

Prefer a code/test fix for a product defect. Amend existing owning guidance for
a durable workflow lesson; remove duplication instead of growing a second rule.
Keep project requirements local. A common change needs a transferability review
and the native AGENTS layer or matching skill that actually exposes it.

Use Core's compact capture/record/observe path in the existing private state.
Codex performs the edit and appropriate verification. Record actual follow-up
only when independent work supplies it. Unknown exposure or missing opportunity
does not establish success. Contextual behavior is separate from causal gains.

An aggregate audit is optional diagnosis: read [weekly audit](../../references/weekly-usage-audit.md)
only for a concrete usage question or an explicit audit request. No change quota,
whole-history scan, model comparison, or external lookup is required by default.
Preserve settings, authority, native history and consent. Ordinary work does not
need a GroundLine record. Assessment-only requests remain read-only.
