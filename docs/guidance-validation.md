# Validate useful guidance

Source and package checks validate callable metadata and links; they do not
prove behavioral improvement. Core exposes one implicitly callable improvement
skill. Installation and model-selection requests use native maintenance rather
than selecting this skill.

For a guidance change, check the existing criterion, relevant context and a
counterexample. Verify actual scoped file content and its native exposure path.
Code defects belong in code/tests. Project-specific requirements stay local;
common rules require transferability and no competing owner.

The compact CLI's isolated regression cases cover target scope, symlinks and
hardlinks, private inputs, no-change exits, duplicate/conflicting observations,
later user edits and unknown exposure/opportunities. They test software behavior,
not the live assistant's compliance. Preserve old records and settings byte for
byte when validating a candidate; never create synthetic natural observations
in the real store.

Natural follow-up assesses only later independent work. Read the actual trigger,
applicable criterion, guidance exposure and resulting behavior. Record met,
violated or unassessed without requiring model/tier/tool equality. Unknowns stay
unknown. Compare completion, rework, user intervention and time only when actual
evidence supports the comparison; causal or resource claims need their own
design. Core's contextual readout deliberately never verifies those claims.

A review with no new evidence ends normally. Do not rescan unchanged history,
run the weekly audit repeatedly or fabricate opportunities to fill a quota.
The long-term product question is whether useful corrections and saved user
effort exceed review and maintenance cost. Record count is not a success metric.
