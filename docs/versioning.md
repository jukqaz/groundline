# 릴리스 버전

GroundLine은 릴리스 날짜와 그날의 순번을 사용합니다. 정본은 루트
`Cargo.toml`의 `workspace.package.version`에 저장하는 숫자 SemVer
`year.MMDD.ordinal`입니다. 월·일은 하나의 정수로 합치고 앞의 0을 생략하며,
당일 순번은 1부터 시작합니다. 릴리스 날짜는 한국 시간 기준으로 선택하며
빌드 시각이나 실행 환경에 따라 자동으로 바꾸지 않습니다.

| 숫자 정본 | 표시 이름 | 의미 |
| --- | --- | --- |
| `2026.929.1` | `2026.09.29-a` | 9월 29일 첫 릴리스 |
| `2026.929.2` | `2026.09.29-b` | 같은 날 두 번째 |
| `2026.929.26` | `2026.09.29-z` | 같은 날 26번째 |
| `2026.929.27` | `2026.09.29-aa` | 같은 날 27번째 |
| `2026.930.1` | `2026.09.30-a` | 다음 날 첫 릴리스 |

`groundline-contracts::version::release_display_name`이 Gregorian 날짜와
양수 순번을 검증하고 표시 이름을 파생합니다. 년도는 1~9999이며 윤년 규칙을
적용합니다. 별도 표시 버전 파일이나 자동 업데이트 상태는 두지 않습니다.

```bash
cargo run --quiet --locked -p xtask -- release-name --version 2026.929.1
# 2026.09.29-a
```

`--version`, 두 플러그인의 `plugin.json`, 바이너리 artifact manifest,
Insights 전송 버전, 설치 캐시 경로는 모두 숫자 정본을 사용합니다.
Git 태그는 `v2026.929.1`, GitHub 릴리스 제목은 공용 변환 결과를 사용한
`GroundLine 2026.09.29-a`입니다. 표시 이름을 API나 설치 버전으로 보내지 않습니다.

릴리스 준비 시 workspace·내부 dependency·lockfile·두 플러그인 manifest를
같은 숫자 버전으로 맞춥니다. `verify-source`와 `verify-package-set`이 버전
일치 및 새 날짜 형식을 검증합니다. 같은 날에는 순번을 늘리고 날짜가 바뀌면
1부터 시작합니다. 이미 게시한 태그·asset은 교체하지 않습니다.

stable 승격은 현재 버전보다 큰 후보만 허용하며 날짜 또는 당일 순번의
역행과 같은 버전의 다른 commit을 거절합니다. 이미 승격한 같은 commit만
변경 없는 재확인이 가능합니다. SemVer 정렬이 일·월·년 경계에서도 이 순서를
유지합니다.

기존 `0.x.y` 기록과 API 전송은 계속 strict 숫자 3부분 버전으로 검증합니다.
CalVer 날짜 검사는 새 릴리스의 표시·패키징 경계에 적용하며 과거 기록을
재작성하거나 표시 이름으로 변환하지 않습니다. 버전의 숫자 증가 자체는
API·데이터 schema 호환성 보장이 아니므로 [릴리스 체크리스트](release-checklist.md)의
현재 계약 검증을 함께 수행합니다.
