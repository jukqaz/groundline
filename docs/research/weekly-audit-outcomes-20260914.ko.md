# 주간 감사 결과 판정과 Astra 지침 적용

확인일: 2026-09-14. [현재 Astra 가이드](https://developers.openai.com/api/docs/guides/latest-model#prompting-best-practices)의
승인된 작업 지속, 충돌하는 지침 점검, 필요한 검증 완료 원칙을 유지한다.
모델 변경이나 성능 향상을 전제하지 않고 실제 집계 오류와 실행 경로를 수정한다.

| 재현 입력 | 이전 판정 | 수정 후 |
| --- | --- | --- |
| 종료 코드 0, 성공 테스트 이름에 timeout/rejected 포함 | 실패 | 성공 |
| 네이티브 텍스트의 `Process exited with code 1` | 성공 | 실패 |
| 종료 코드 없음, 실행 session 존재 | 성공 | 실행 중·미해결 |
| 종료 증거 없는 임의 출력 또는 외부 실행기 완료 | 성공 | 미확인·미해결 |
| 추천 명령에 `--audit -` | 일반 파일 검사에서 거절 | 최대 2 MiB 표준입력 |

JSON 판정은 현재 Codex의 text/content 봉투와 settled batch 안의 결과
메타데이터만 읽고 대형 본문은 버린다. 일괄 결과는 모두 성공이 확인되어야
성공으로 판정하고, 일부 실패·실행 중·미확인은 그대로 보존한다. 텍스트 판정은
네이티브 머리말에서만 종료 코드를 읽는다. 미확인 결과에 종료 코드 0을 만들지
않는다. 별도 도구 호출로 수행한 poll이 원래 호출과 연결되지 않으면 미해결로
남기므로 검증 성공률에는 결과 커버리지를 함께 제시한다.

주간 자동화는 활성 설치 목록에서 정확한 버전을 선택하고 동일 설치의 지침과
바이너리를 사용한다. 홈 전체 검색과 캐시 폴더의 문자열 정렬로 설치를 추정하지
않는다. 집계는 한 번만 읽고 그 결과를 메모리에 보관해 추천으로 전달한다.
생산자와 추천 명령의 종료 상태를 따로 확인한다.

완료 턴 수를 작업 수로 표시하지 않는다. 사용량은 선택된 rollout 중 관측된
비율과 출처를 표시하며, 입력에 포함된 캐시나 출력에 포함된 추론 토큰을
다시 더하지 않는다. 프롬프트 텍스트가 없거나 Guardian 속성을 읽지 않았으면
관측 불가로 남긴다. 알려진 상속 prefix 제외와 소유권이 불명확한 수집 문제를
분리하고, 불완전한 증거로 모델 설정을 바꾸거나 데이터를 삭제하지 않는다.

현재 로컬 감사는 요청한 기간을 새 파서로 재계산한다. 수집 완료된 서버 이벤트는
원래 버전과 함께 보존하며, 0.25.6 이전의 실패 신호·검증 결과를 새 수집 지표와
동일한 의미로 비교하지 않는다. 토큰 집계와 수집 커서는 변경하지 않는다.

검증 경계는 파서 회귀, 실제 CLI 표준입력, 수집 이벤트 계약, 설치된 바이너리의
주간 감사와 추천 경로다. 이것만으로 Astra 자체의 완료율이나 비용 개선을
입증할 수는 없다.
