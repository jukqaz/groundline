# Astra와 Codex 중심 GroundLine 정비

확인일: 2026-09-11

GroundLine은 Codex의 판단과 실행을 보조하는 플러그인·CLI로 유지한다.
별도 Desktop 앱은 종료한다. 현재 지침은 Astra의 특성과 대체로 맞지만,
일부 필수 절차와 작업 경계 판정이 실제 요청보다 넓게 적용되고 있었다.
이번 변경은 그 충돌을 수정하며, Astra 성능을 최대화했다고 주장하지 않는다.

## 공식 자료에서 확인한 기준

Astra는 여러 도구에 걸친 장기 작업과 사용자 수정 지시를 처리하도록 설계됐다.
공식 가이드는 불필요한 확인 질문, 서로 충돌하는 스킬·AGENTS.md, 과도한 응답
형식, 작은 변경의 지나친 테스트가 작업을 방해할 수 있다고 설명한다.
위임 예시는 각 환경에 맞게 조정하는 지침이며 사용자의 위임 정책을 바꾸는
근거로 사용하지 않는다. [Astra 가이드](https://developers.openai.com/api/docs/guides/latest-model#prompting-best-practices)

Codex에는 목표, 관련 맥락, 제약, 완료 기준을 제공하고 반복되는 실제 문제를
짧은 저장소 지침으로 정리한다. GroundLine의 별도 실행 제어기를 추가하기보다
현재 Codex의 도구와 컨텍스트 관리를 사용한다.
[Codex 권장 작업 방식](https://learn.chatgpt.com/guides/best-practices)

스킬은 하나의 작업에 집중하고, 설명으로 선택한 뒤 필요한 본문과 참조만
읽도록 구성한다. 따라서 모델 지침 조사에 개인 집계 보고서와 인증 정보를
항상 요구하는 것은 적절하지 않다. 마지막 문장은 GroundLine 소스와 요청
범위를 대조한 설계 판단이다. [스킬 작성 가이드](https://learn.chatgpt.com/docs/build-skills)

## 확인한 문제와 변경

| 기존 동작 | 수정 |
| --- | --- |
| 작업 결과·저장소·권한이 달라지면 `new_task`, 대안을 검토하면 `fork` 권고 | 현재 작업에서 `reconcile` 또는 `stay`; 새 작업·분기는 명시 요청 신호가 있을 때만 권고 |
| 마지막 검증 중 범위가 바뀌어도 이전 증거로 완료 권고 가능 | 바뀐 범위를 다시 확인하고 검증하기 전에는 기존 Goal 완료를 권고하지 않음 |
| 모델 지침 조사에도 Insights 보고서·주간 감사·개인 실험 계약을 먼저 요구 | 공식 문서와 관련 지침을 검토하는 경로를 분리; 개인 데이터 실험은 별도 요청 시 수행 |
| 실행 확인에서도 플러그인 출시·설치·새 작업 증거를 모두 요구 | 요청한 실행 결과에 필요한 증거만 확인; 업그레이드 요청일 때 출시 계약 적용 |
| 일반 지침 정비와 설치 프리셋 적용의 경계가 불명확 | `setup`은 해당 설정 적용 요청에만 사용; 다른 모델·추론·서비스 선택은 유지 |
| 전처리 단계·Goal 없음·출력 양식이 실행보다 앞설 수 있음 | 다음 행동이 명확하면 진행하고, 필요한 경우에만 단계·예산·Goal을 기록 |

세부 지침은 [모델·추론 가이드](../../plugins/groundline/references/model-effort-routing.md)에
모으고 조건부 참조로 유지한다. 새 자동 스킬이나 상시 실행 훅은 추가하지 않았다.
Core는 오프라인, Insights는 별도 동의를 받은 집계 수집이라는 경계를 유지한다.

## Desktop 종료 후 구성

```text
Codex App / CLI
  ├─ Core 플러그인·CLI: 지침과 로컬 진단
  └─ Insights 훅·CLI: 수집·전송 → Insights API → ClickHouse
                                           └→ CLI 보고서 / Grafana
```

Desktop 소스, 프론트엔드와 Tauri 의존성, GUI 빌드·릴리스 작업, 전용 준비 상태
함수를 제거했다. 이전 앱의 작업 중 변경은 저장소 밖에 보관한다. 공통 CLI의
등록·전송 준비 검사와 수집 중지 보호는 유지한다. `codex_app`·`codex_cli`와
`desktop` 실행 모드는 데이터 출처이므로 앱 종료와 무관하게 유지한다.
기존 서버 설정·동의·인증 정보·커서·미전송 이벤트는 초기화하지 않는다.

## 검증과 적용 경계

결정적 검증은 [지침 검증 문서](../guidance-validation.md)의 Rust 계약 테스트,
CLI 회귀 테스트, 스킬 메타데이터·링크, 소스·CI 검사로 수행한다. 특히 범위가
바뀐 뒤의 완료 판정, 질문 후 계속 실행, 명시 요청 없는 작업 생성 억제를 확인한다.

설치된 0.24.6 Core·Insights의 패키지 검사와 모델 설정·현재 카탈로그 대조는
소스 수정의 설치 적용 증거가 아니다. 새 지침의 실제 로딩, Astra의 작업 완료율,
재질문·재작업 감소는 **UNVERIFIED**다. 효과를 비교하려면 모델·추론 수준과
작업 조건을 유지하고 직접 확인한 결과를 사용해야 한다. 토큰·시간 감소만으로
품질 개선이나 인과관계를 단정하지 않는다.

이 문서는 소스와 로컬 검증의 근거다. 공개 릴리스, 설치 캐시 갱신, 새 수집 전송,
운영 API 배포 결과는 해당 버전의 적용 증거로 별도 기록한다.
