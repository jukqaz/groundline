# 조사에 따른 GroundLine 개선사항

상태: 2026-10-06 개선안과 [첫 로컬 구현](adaptive-environment-implementation.md).
소스·단일 기기 검증과 지속적인 업무 효과·다중 기기 적용·배포를 구분합니다.
[현재 재설계](adaptive-environment-design.md)의 보완 항목과 구현 완료 기준입니다.
적용·복구의 파일 안전성은 [경계 조건 조사](adaptive-environment-safety-research.md)를 따릅니다.

## 방향과 공식 기준

목표는 개인의 사용 패턴·실제 결과·현재 모델의 권장 방식을 연결하여 Codex 환경을
개선하고 여러 기기에 같은 의도를 적용하는 것입니다. 실행과 기억·skills·agents·권한은
native Codex를 사용합니다. GroundLine은 개선 근거, 환경 revision, 실제 적용과 다음
결과를 연결합니다. 개선할 이유가 없는 경우에는 변경하지 않습니다.

공식 근거를 우선하며 비교 프로젝트의 기능은 필요한 설계 패턴만 참고합니다.

| --- | --- | --- |
| [Codex memories](https://learn.chatgpt.com/docs/customization/memories) | 기억은 유용한 회상 계층이며 필수 지침은 AGENTS/문서에 둠. 생성 상태와 사용·생성 제어가 별도 | native 기억 기능과 사용자 선택을 유지. 생성된 기억 파일을 관리 기준이나 동기화 payload로 삼지 않음 |

실제 가용 상태는 다릅니다. 아래 비교도 설치·실행 시험이 아닌 문서·소스 조사입니다.

## I01·I02: 신뢰할 수 있는 관측부터 연결

현재 native audit·Insights·delivery 근거를 재사용합니다. Core는 hook-free를 유지하며,
필요한 Insights event만 해당 host의 native 지원과 trust에 맞춰 사용합니다.
새로운 상주 observer나 턴마다 실행되는 LLM reflection을 추가하지 않습니다.

- 수집 실패, 분석 실패, 결과 미관측, 관련 기능 미지원은 별개의 상태입니다.
  hook 설정이나 기억 파일의 존재만으로 수집 성공을 표시하지 않습니다.
- memory 생성/사용이 꺼졌거나 지연·생략된 경우를 정상 지원 상태와 구분합니다.
  사용자가 정한 기억·수집 범위를 넓히거나 native 생성 상태를 직접 고치지 않습니다.
- 작업의 기존 `unit_hash`·phase·cohort와 근거를 재사용해 필요한 revision만 연결합니다.
  환경 기준/관측 시점, 대상 skill revision, 공식 자료 revision의 미관측은 unknown입니다.
- 실제 root/child 모델 ID·effort를 유지합니다. 설정·요청·실행 관측을 나누고,
  child를 root 모델로 채우거나 `gpt-6.1-sol`을 다른 ID로 합치지 않습니다.
- 사용자 메시지의 추가 요구·방향 변경·수락·정정과 assistant 오류의 재작업을 구분합니다.
  후속 질문이나 사용자 침묵을 오류·수락으로 자동 분류하지 않습니다.
- 기존 delivery의 근거 hash는 내용 식별자입니다. operator-supplied 기록만으로
  `activation_verified`·`authenticity_verified`를 참으로 바꾸지 않습니다.

개인 교훈·원문·설정·경로는 owner-private 근거에 남깁니다. 기존 Insights 전송 범위를
학습 설계만으로 확대하지 않습니다. 공개 설계에는 계약과 비식별 예시만 둡니다.

## I03·I05: 작은 변경과 정확한 재사용

후보는 기존 설계의 ID·basis/source revision·범위·권한·검증·복구 근거를 사용합니다.
추가로 교훈의 식별/중복 기준, 대상의 owner와 현재 revision, 의도한 발동 조건,
수정·축소·제거 이유를 연결합니다. 정확한 저장 schema는 첫 구현에서 확정합니다.

명시 선호는 해당 범위의 기준이고 반복 관측은 가설입니다. 같은 교훈이라도 프로젝트·
작업 종류·모델이 다르면 합치기 전에 근거를 확인합니다. 사용자 정정은 원래 규칙의
대체·범위 축소 후보로 연결하여 충돌하는 새 규칙을 계속 덧붙이지 않습니다.
후보 분석 실패 시 원본 근거를 처리 완료로 폐기하지 않습니다.

| 교훈의 종류 | 적합한 위치 |
| --- | --- |
| 과거 작업의 회상 | 사용자 선택에 따른 native memories와 기존 작업 맥락 |
| 반복 workflow의 절차·명령·자료 | 등록된 개인/프로젝트 skill과 필요한 reference |
| 항상 적용할 짧은 작업 원칙 | 허용된 AGENTS 구간 또는 프로젝트 지침 |
| 모델·effort·권한·네트워크의 명시 선택 | 사용자 소유 config와 native 정책의 해당 범위 |
| 기기 경로·지원 차이 | 개인 기준의 기기 예외 |

환경 관리 범위를 새로 등록하거나 config·권한을 바꾸는 일은 가설이 대신 승인하지 않습니다.
bundled/hub/provider cache는 직접 수정하지 않습니다. 공용 GroundLine의 개선이 필요한
교훈은 비공개 원문을 제거한 문제·재현·변경으로 공용 개발 경로에 연결합니다.

스킬 활용은 관련 기회를 확인한 경우에만 판단합니다. 목록 노출, 본문 로드/호출,
절차 실행, 결과 확인을 구분하고, native 기록이 없는 단계는 unknown으로 둡니다.
호출이 없다는 이유만으로 실패를 판정하지 않습니다. 스킬 개수의 임의 상한이나
빈도 순위를 품질로 사용하지 않습니다. 사용량이 적은 필수 규칙도 자동 삭제하지 않습니다.

## I04·I08: 품질과 전체 비용으로 후속 판단

기존 상태 흐름을 유지합니다: 관측→가설→적용→관측 중→유지/수정/복구.
형식 검사와 native 로딩을 통과하면 적용 근거가 생기며, 효과는 다음 실제 업무로 확인합니다.
대조 가능한 기준 결과가 없으면 이후 성공 한 건만으로 개선율·인과효과를 보고하지 않습니다.

| 판단할 결과 | 필요한 근거 |
| --- | --- |
| 업무 품질 | 해당 작업의 완료·필수 검사·수락 근거, 실패·재작업과 미완료 |
| 과정과 재사용 | 관련 기회·스킬 revision·실제 호출/실행, 불필요한 사용자 개입의 확인 근거 |
| 효율 | 소유된 root/child/실패/재시도 자원, 분석·리서치·검증·환경 관리 비용과 누락 범위 |
| 환경 일치 | 해당 host의 원하는/기록된/활성 revision, 의도한 예외와 부분 실패 |

토큰은 동일 response의 중복과 포함 관계를 제거합니다. 입력/출력/캐시/추론의 하위
항목을 총 토큰에 다시 더하지 않습니다. 분석이 작업 자원에 이미 포함돼 있으면 재합산하지
않습니다. 병렬 child의 경과 시간을 더해 완료 시간으로 쓰지 않으며 토큰을 구독 한도로
환산하지 않습니다. 지침별 로딩 비용을 정확히 분리하지 못하면 추정 또는 unknown으로 둡니다.

작업 난도·완료 기준·모델/effort·runtime·권한·도구·기기·지침 변화가 비교에 영향을
주면 구분해 보고합니다. 관측상 상관과 검증한 개선을 나누고 기존 비교 계약을 유지합니다.
추가 행동 실험은 요청한 범위와 한도에서만 실행하며 완료된 작업을 표본 확보용으로 재실행하지 않습니다.

LLM 분석은 요청한 검토, 관련 반복 마찰, 의미 있는 모델/환경 변화에서 필요한 근거만
읽습니다. 근거/관련 revision이 같으면 재사용하고 무변경·이미 처리한 후보의 반복 분석을
억제합니다. 소요·중복·실패와 미확인 자원을 기록하고 별도 분석 한도를 몰래 늘리지 않습니다.
native 자동화는 사용자가 요청한 일정과 범위에 연결하며 이 문서로 새 일정을 등록하지 않습니다.

위임은 독립 작업의 정확성·시간 이득과 전체 비용을 함께 판단합니다. 현재 상속 설정을
유지하고 역할별 고정 모델·필수 agent 수·반복 리뷰를 만들지 않습니다. 모델 선택 요청에
대한 추천은 현재 catalog와 해당 작업 근거를 사용하며 추천과 실제 선택을 구분합니다.

## I06·I07: 환경 적용과 모델 변화

공통 기준은 등록한 파일/키/구간과 명시 선호를 관리하고 host 예외는 이유·소유자를
갖습니다. App/PATH는 같은 파일을 가리켜도 로딩·기능 지원을 따로 확인합니다.
다음 세션 반영·hook trust 필요·plugin 업데이트 필요·unknown을 실제 활성과 구분합니다.

inspect/plan/apply/rollback의 준비 기록·조건부 갱신·경로 binding·부분 복구 의존성과
필수 실패주입 회귀는 기존 안전성 문서를 따릅니다. 개인 학습의 새로운 writer가
이 경계를 생략하지 않습니다. native 세션/캐시/DB/기억 생성 상태·자격증명은 동기화하지 않습니다.

공식 자료는 URL·확인 시각·digest·적용 모델/runtime과 영향받는 규칙을 연결합니다.
문서나 모델이 바뀌면 관련 규칙만 재검토하며 공통 기준·해당 skill revision·다음 결과로
연결합니다. 공식 모델 지침의 변화가 명시 선호나 권한의 자동 변경을 허용하지 않습니다.
원문 비교 실패·자료 미확인·host 미지원은 미확정으로 남깁니다.

## 첫 구현 범위와 순서

기존 설계의 0~3단계를 다음과 같이 구체화합니다. 작은 첫 순환을 먼저 완성합니다.

| 단계 | 구현 범위와 담당 모듈 | 다음 단계로 넘길 근거 |
| --- | --- | --- |
| 0: 현재 환경·근거 | I01·I02·I08. contracts/runtime의 audit·delivery 연결과 관련 CLI/Insights 표시 | 현재 Mac App/PATH, 당시 revision, 결과·자원·누락 원인의 연결. 모델 패턴은 PR #57 병합/실제 연결 상태 확인 뒤 재사용 |
| 1: 환경 계약 | I06. shared runtime의 개인 기준·예외·영수증·제한 적용/복구 | 등록된 가역적 대상, 정확한 diff와 native 확인. 안전성 회귀·충돌 보존 통과 |
| 2: 학습 연결 | I03·I04·I05. 후보·후속 결과 계약과 기존 비교/skill 경로 | 한 종류의 실제 반복 마찰→기존 skill의 작은 수정→적용 확인→자연스러운 다음 업무와 기준 결과 비교. 부족하면 관측 중 |
| 3: 지속 개선·확장 | I07와 다른 기기의 I06, 명시 정책 아래의 반복 억제 | 관련 공식 변경·다른 host 영수증·범위 내 자율 갱신과 비용·복구 근거 |

첫 순환은 기존 등록 skill 하나의 trigger·본문/참조 수정처럼 작은 변경으로 제한합니다.
역할별 새 agent 묶음·별도 기억 서비스·상시 GEPA 학습·전 설정 재작성은 초기 구현 범위에
포함하지 않습니다. 코드 변경 시 데이터·상태 전이·중복/누락·scope·충돌 회귀를 수행합니다.
문서 검사나 합성 테스트 통과를 실제 환경 적용·업무 효과 확인으로 보고하지 않습니다.
