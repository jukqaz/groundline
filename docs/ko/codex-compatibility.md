# Codex 업데이트 대응

GroundLine은 Codex의 모델 선택, 권한, 컨텍스트 관리, 플러그인 업그레이드를
그대로 활용합니다. 모델명이 늘어날 때마다 별도 실행 엔진을 수정하는 구조가
아니며, 실제 데이터 형식이나 집계 규칙이 바뀌면 해당 읽기 경계만 수정합니다.

- 모델 추천은 현재 실행 환경의 카탈로그를 확인합니다. Astra도 지원하지만
  글로벌 기본 모델이나 추론 강도를 강제로 고정하지 않습니다.
- 모델 계열·추론 강도 분류는 Rust 공통 모듈 한 곳에서 관리합니다. Astra는
  독립 계열로 집계하고, 알 수 없는 모델명은 개인정보를 내보내지 않는 `other`로
  처리합니다. 모델별 문맥 횟수는 모델별 토큰 사용량이나 비용을 뜻하지 않습니다.
- Codex의 최신 숫자 버전 상태 DB를 읽기 전용으로 선택하고, 일반 JSONL과
  Zstandard 압축 기록을 같은 읽기 경로에서 처리합니다.
- 주간 표본은 마지막 턴이 완료된 작업을 선택합니다. 이전 턴이 끝났더라도
  다시 진행 중인 작업은 완료 표본에 넣지 않습니다. 활동 집계에는 포함됩니다.
- 서로 다른 작업의 도구 결과·모델 변경이 섞이지 않도록 분리하며, 같은
  컨텍스트 압축에 대응하는 두 기록은 한 번만 셉니다.

2026-09-05 확인한 [공식 릴리스 노트](https://learn.chatgpt.com/docs/changelog)의
CLI 0.153.4에는 Astra 모델 선택기·기본값과 비동기 질문 가이드 수정이 있습니다.
앱 내장 CLI와 PATH CLI는 별도로 확인해야 합니다. 실험적 컨텍스트 관리는
지원 계정·환경의 명시적 선택이며 GroundLine이 자동으로 켜지 않습니다.

기록 하나당 압축 해제 64 MiB, 감사 한 번당 512 MiB 상한을 적용합니다.
읽지 못한 기록은 결과에 드러납니다. 최신 공유 이력은 Codex의 순서 경계로 현재
작업 구간만 구분하고, 작업 ID가 일치하는 응답별 사용량을 중복 제거해 집계합니다.
부모의 누적 사용량을 더하지 않으며, 읽지 않은 부모 구간은 `PARTIAL`로 표시합니다.
구간 경계가 없는 과거 분기 기록은 계속 제외합니다. 심볼릭 링크 DB·세션 루트와
전체 공유 이력 복원은 지원하지 않습니다.

Insights에서 새 모델 계열·사용량 출처를 전송하는 버전은 **API를 먼저 올리고
collector를 업데이트**해야 합니다. 기존 API는 알 수 없는 값을 거부할 수 있습니다.
저장된 인증 토큰이 있어도 `/healthz`의 수집 계약을 먼저 검사하며, 비호환이면
`api_upgrade_required`로 중단하고 대기 데이터를 보존합니다.
이 리팩터링은 수집 동의·대상 서버·활성화 상태를 변경하지 않습니다.

최초 수집 범위는 최근 7일입니다. 이후에는 저장된 수집 완료 시각을 유지합니다.
작업을 나중에 이어서 사용해도 이전 구간의 이벤트를 제외하지 않습니다.
읽기 실패 구간은 시작·끝 시각을 고정한 채 보관하고, 완전하게 읽힌 집계만
전송합니다. 자동 시도는 구간당 3회로 제한하며 이후에는 원인을 해결한 뒤
`groundline-insights worker run-once`로 명시적으로 재시도합니다.
이미 전송한 과거 집계는 자동 재수집하지 않습니다.

독립 작업의 신규 응답 누적값과 기존 누적값은 하나의 기준으로 비교합니다.
포함 범위를 확인할 수 없는 혼합 기록이나 누적값 초기화는 불완전으로 표시합니다.
오류 예시는 최대 32개만 남기고 나머지는 개수로 집계합니다. 파서 상한은
한 번에 100만 레코드, 레코드당 4 MiB입니다. 알려진 부모 구간 제외와 실제
현재 작업의 읽기 실패를 구분하므로 작은 표본만으로 수집을 중단하지 않습니다.

세부 계약과 검증 범위는 [영문 문서](../codex-compatibility.md)를 참조하세요.
